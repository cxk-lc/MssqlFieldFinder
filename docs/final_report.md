## 2. 启动方式

### 2.1 直接运行打包产物（推荐给使用者）

```
双击  MssqlFieldFinder\MssqlFieldFinder-v1.6.0.exe
```

目标机器**不需要安装 Python**，但需要安装 `Microsoft ODBC Driver for SQL Server`（缺失时
程序会在配置弹窗中给出红色下载链接）。配置文件 `config.json` / `connections.json`
生成在 exe 所在目录，因此拷贝时把两个 json 一并带走即可保留连接方案。

体检命令（在 cmd 中执行）：

```bat
MssqlFieldFinder\MssqlFieldFinder-v1.6.0.exe --check      :: 打印版本/配置目录/驱动/方案
MssqlFieldFinder\MssqlFieldFinder-v1.6.0.exe --version    :: 只打印版本号
```

### 2.2 从源码运行（开发调试）

```bat
bat\run.bat

:: 或显式指定解释器
C:\Users\admin\.workbuddy\binaries\python\envs\mssql_scanner\Scripts\python.exe main.py
```

前置依赖：① 含 tkinter 的 Python 3.9+；② `pyodbc`；③ 目标机已安装
**Microsoft ODBC Driver for SQL Server**（本机检测到 17 / 11 / Native Client 11.0）。
不确定时先运行 `bat\诊断环境.bat`。

### 2.3 重新打包（迭代时）

```bat
bat\build.bat
```

或参看《打包说明.md》中的手工命令与参数说明。

## 3. 打包与分发

| 项 | 内容 |
| --- | --- |
| 命令 | 双击 `bat\build.bat`（或 `bat\build.bat -y` 不暂停，供自动构建） |
| 产物目录 | `MssqlFieldFinder\`（= 程序名，**不带版本号与扩展名**，可累积多个版本） |
| 产物文件 | `MssqlFieldFinder\MssqlFieldFinder-v<版本>.exe`，单文件，10.2 MB |
| 名称/版本来源 | `src\__init__.py` 的 `__app_name__` 与 `__version__`（唯一来源，改一处即可） |
| 构建参数 | 全部集中在 `MssqlFieldFinder.spec`；脚本只负责找解释器、读名称与版本、拼 `--distpath`、报结果 |
| 构建机要求 | Windows x64 + 含 tkinter 的 Python + `pyodbc` + `PyInstaller`（缺失时脚本自动安装） |
| 目标机要求 | Windows x64；**无需 Python**；需要 ODBC 驱动 |
| 已排除的库 | numpy / pandas / matplotlib / PIL / PyQt / pytest 等（本工具不用，排除后体积明显下降） |
| 校验 | 脚本输出产物目录、文件名、字节数与 SHA256 |

设计取舍：

- **产物目录用固定名、文件名带版本号**：同一个目录可以累积多个版本的 exe（v1.6.0、v1.6.1 …）
  便于回退比对；目录名不含版本，脚本、快捷方式与文档里的路径就不必随版本一起改。
- **单文件 vs 目录版**：默认单文件，分发最省事；代价是启动需解包到临时目录（约 1~3 秒）。
  spec 文件末尾附了切换为目录版（启动更快）的改法与说明。
- **无控制台**：GUI 程序不需要黑框；但保留窗口化 traceback，启动即崩时会弹窗提示，
  而不是静默退出。
- **配置就近存放**：程序以 `sys.executable` 的父目录作为配置目录，所以 exe 放哪、配置就生成在哪，
  即产物目录内。

## 4. 功能实现对照

| 需求 | 实现 |
| --- | --- |
| 连接指定 SQL Server 数据库 | 支持 SQL Server 身份验证与 Windows 集成认证；服务器/端口/命名实例（`HOST\SQLEXPRESS`）；连接超时与查询超时可配 |
| 查找包含指定字段的表 | 阶段 A：一次拉取整库列元数据（全部 schema 的用户表 + 视图），客户端过滤字段名 |
| 在这些表中找字段值包含指定内容的表 | 阶段 B：对每个命中列下推参数化 SQL，命中即回填结果表（架构 / 表或视图 / 类型 / 字段 / 字段类型 / 命中行数 / 示例值） |
| 精准查询与模糊查询 | 两个阶段**各自独立**可选：精准 = 等值；模糊 = 包含 |
| 是否忽略大小写 | 单开关同时对两阶段生效，且与服务器排序规则解耦 |
| 多线程查找 | 自管理线程池，默认 8 线程（可调 1~64），每线程一条独立连接 |
| **连接设置可保存多个方案供选择** | 「配置方案」区：下拉切换 + 新增 / 编辑 / 删除；方案只存连接参数，存于项目目录下的 `connections.json`；支持从历史设置自动播种首个方案 |
| **连接设置不显示在主窗口** | 主窗口只保留配置方案 / 检索条件 / 高级设置；连接参数、**记住密码（默认勾选）**、**测试连接**都在「新增 / 编辑」弹窗中 |
| **测试连接结果可视化** | 弹窗底部一行「指示灯 + 文案」：灰=未测试、黄=测试中、绿=测试成功、红=连接失败（文案同步着色，不依赖颜色也能判断）。成功文案只含**结果 / 当前库 / 登录身份**，超宽自动折行 |
| **记住密码按方案独立** | 每个方案各有自己的「记住密码」开关，默认勾选；关掉某个方案不会影响其他方案的密码 |
| **检索即落盘** | 点击「开始检索」且校验通过后，自动把检索条件写入设置文件；两个关键词写入但不在启动时读回，因此界面每次启动都是空的 |
| **并发线程数自适应** | 默认值按本机 CPU 核数推导（钳制 4~12），并在字段提示与启动日志中说明推导依据 |
| **提示文字布局优化** | 左侧表单加宽至窗口 38%，输入框收窄到 18 字符，提示列换行宽度 132→150；长提示逐条改写为短句；结果提示随窗口宽度动态折行；弹窗各区块加分隔线 |
| **ODBC 驱动检测与下载引导** | 弹窗中检测本机是否有可用的 SQL Server 驱动；缺失时在 ODBC 配置项下方显示红色下划线提示，点击用系统浏览器打开官方下载页 |
| **网格选中：单元格 / 行 / 列** | 点击单元格只选中该格；点击序号左侧空白列选中整行；点击列名选中整列；三态互斥，点击空白区清空 |
| **双击查看命中数据** | 启用内容检索时，双击单元格打开「命中数据」窗口，展示该表满足条件的实际行（最多 200 行，可一键复制全部）；未启用内容检索时双击不做任何动作 |
| **复制入口精简为四项** | 右键菜单：复制单元格 / 复制所在行 / 复制所在列 / 复制全部结果；Ctrl+C 复制当前选中对象 |
| **配置文件迁至项目路径** | `config.json` / `connections.json` 落在项目根目录；旧 `%APPDATA%` 路径仅作只读回退，不删除旧文件 |
| **清除默认配置内容** | 落盘时逐项与默认值比较，只保留有差异的项；各项均为默认值时**不生成文件** |
| **移除保存设置按钮** | 改为关闭窗口时静默保存；方案的新增/编辑本身即为显式保存动作 |
| **检索关键词默认空** | 字段名关键词与内容关键词标记为不持久化，每次启动恒为空 |
| **配置入口改为按钮** | 配置方案框不再显示 json 路径文字，改为「打开设置文件 / 打开方案文件」按钮 |

### 附加能力

- **测试连接**：在方案弹窗内一键验证，返回当前库名、登录身份与服务器版本，并以指示灯给出结论。
- **可随时取消**：任务边界生效，未派发的列直接跳过。
- **实时进度**：进度条 + 「已完成/命中/异常/耗时」状态文本。
- **样例值回传**：命中时带出字段实际取值（默认 3 条），便于人工判断是否误报。
- **命中数据下钻**：双击任意结果行即可看到该表里符合条件的真实数据行。
- **存在性 / 计数两种判定**：默认 `TOP(n)` 存在性判定（快），可切换 `COUNT_BIG` 精确计数（慢）。
- **配置持久化**：项目根目录下 `config.json`（非默认设置）与 `connections.json`（命名方案）；
  密码默认不落盘；关闭窗口时静默保存。

## 5. 关键设计要点

1. **只读安全**：全代码仅含 `SELECT` 与 `INFORMATION_SCHEMA` 查询，无任何 DDL/DML；标识符经 `quote_ident()` 转义、取值全部参数化，并有注入用例覆盖。
2. **行为不依赖服务器配置**：内容检索一律追加显式 `COLLATE Latin1_General_CI_AS / CS_AS`，避免「忽略大小写」在 CS 服务器上静默失效。选用 `Latin1_General` 而非 `Chinese_PRC`，是为了规避非 Unicode 排序规则绑定代码页 936 带来的隐式转换风险。
3. **线程安全边界清晰**：pyodbc 连接对象非线程安全，故按线程隔离连接；工作线程只向队列投递事件，Tk 控件仅由主线程经 `after(80ms)` 轮询更新。
4. **逻辑与 IO 分层**：`matcher / sqlbuild / connstr / drivers / models / profiles / paths` 均无 IO 依赖，可脱离数据库证明语义正确；引擎通过注入「连接工厂」用假连接完成并发与错误路径测试。
5. **生产库友好**：默认 `WITH (NOLOCK)` 避免阻塞业务写入，语句级超时防慢表拖死线程，并有最大检索列数上限防止误配全库扫描。
6. **选中态用单一结构表达互斥**：`GridSelection(kind, row, col)` 中 `kind` 只能取一个值，任一 setter 重置其余两者——互斥由数据结构保证，而非靠多个布尔量互相清零。
7. **单元格高亮自绘边框**：Tk Treeview 只支持整行选中，故用四条 2px 边框围出轮廓；不填充内部，因此不遮挡文字，并随滚动/缩放同步、目标不可见时自动隐藏。
8. **配置语义分离且最小落盘**：`config.json` 是「改过的设置」，`connections.json` 是「命名方案」；两者都只写非默认内容。

## 7. 已知限制

1. **仅有假连接验证，无真实 SQL Server 联调**：本次环境无可连通的实例，端到端依赖用户首次实测。
2. **仅检索当前数据库**：不遍历实例下的多个库（按需求确认的范围）。
3. **分发仍需 ODBC 驱动**：exe 已自包含 Python 运行时，但 `Microsoft ODBC Driver for SQL Server`
   属系统级组件，无法打进包内，需在目标机单独安装（程序内有红色下载链接引导）。
4. **未做代码签名**：首次运行可能触发 SmartScreen 提示；单文件包也可能被杀毒软件误报
   （PyInstaller 常见现象，可加白名单或改用目录版）。
5. **未附带自定义图标**：产物使用 PyInstaller 默认图标；如需品牌图标，在 spec 的 `EXE(...)`
   中加 `icon=r"path\app.ico"` 即可。
6. **启动需 1~3 秒**：单文件版每次运行要把内容解包到临时目录；改目录版可消除。
7. **特殊类型列**：`Always Encrypted`、`image`、`xml` 等无内建语义，会显现为错误项而不影响其余列。
8. **批次脚本编码为 GBK**：中文 Windows 控制台下的可靠选择；迁移到非中文区域系统需转码。
9. **「命中数据」窗口最多显示 200 行**（硬上限 5000）：用于快速核验，不做全量导出。
10. **检索关键词会写入设置文件**（但不读回）：如不希望留在磁盘上，可改为完全不写入。
11. **旧 `%APPDATA%\MssqlFieldFinder` 目录未删除**：迁移后不再写入，旧文件保持原样以备回退。

1. 把 `MssqlFieldFinder\MssqlFieldFinder-v1.6.0.exe` 拷到目标机器，双击运行。
2. 若目标机没装 ODBC 驱动：打开「配置方案 → 新增」，点击 ODBC 项下方的红色链接安装。
3. 在弹窗里填好连接信息，先点「测试连接」确认底部亮绿灯，再点「确定」保存方案。
4. 建议为生产库、测试库各存一个方案，之后切换库只需点一下下拉框。
5. 初次使用建议先用**单表/小范围精准查询**试跑，确认大小写与模糊语义符合预期，再放到整库。
6. 双击结果行核对命中数据是否合理，再决定是否作为问题线索使用。
7. 若需导入生产库，建议先用只读账号，并确认 `NOLOCK` 是否符合贵司 DBA 规范。
8. 后续迭代：改代码 →（可选）改 `src\__init__.py` 的版本号 → 双击 `bat\build.bat` → 取走新 exe。
9. 还可继续做：结果导出 Excel/CSV、跨库遍历、自定义程序图标、代码签名。
