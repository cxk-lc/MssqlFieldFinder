## 1. 需求（已与需求方确认）

连接指定的 SQL Server 数据库，完成两阶段检索：

1. **阶段 A — 字段定位**：在整库（所有 schema 的用户表 + 视图）中找出「包含指定字段名」的表/视图。
2. **阶段 B — 内容定位**：在阶段 A 命中结果的指定字段里，找出「字段值包含指定内容」的表/视图。

两个阶段均需支持 **精准查询 / 模糊查询** 两种模式，并支持 **是否忽略大小写**。内容检索需支持 **多线程** 以提高效率。

### 1.1 已确认的交付约束

| 决策项 | 结论 |
| --- | --- |
| 交付形态 | Tkinter 图形界面桌面工具 |
| 认证方式 | 同时支持 SQL Server 身份验证 与 Windows 集成认证 |
| 扫描范围 | 整库所有 schema 的 **用户表 + 视图**（排除系统对象） |
| 结果输出 | **仅界面内展示，不导出文件**（结果表 + 运行日志 + 状态统计）；每个字段均可单独复制到剪贴板 |

## 2. 目标与非目标

**目标**

- 面向生产库安全：全程只读，不对业务数据产生任何写操作或长时间锁等待。
- 检索语义明确、可预测：匹配模式与大小写策略在界面上显式可选，行为不依赖服务器默认排序规则这种隐性变量。
- 可中断、可观测：长任务可随时取消，进度与命中结果实时可见。
- 纯逻辑层与 IO 层解耦，保证核心语义可通过单元测试证明。

**非目标（本期不做）**

- 跨实例 / 跨数据库遍历（仅当前所选数据库）。
- 结果导出为 CSV/Excel（需求方明确选择不落盘）。
- 对加密列（Always Encrypted）、`sql_variant`/`image`/`xml` 等特殊类型的语义化检索。
- 无 ODBC 驱动的自包含分发（依赖目标机已安装 Microsoft ODBC Driver for SQL Server）。

## 3. 架构分层

```
表现层    app.py      主窗口 / 事件循环 / 后台线程调度
          widgets.py  滚动容器、表单行、结果表、日志面板
          config.py   字段声明（schema 驱动 UI）+ 配置持久化
               │  （仅通过 queue 交换数据，UI 线程绝不触碰 DB 对象）
引擎层    engine.py   元数据发现 + 线程池并发内容检索 + 取消/超时
               │
纯逻辑层  matcher.py  匹配语义（精准/模糊 × 大小写）
          sqlbuild.py 标识符转义 / LIKE 转义 / COLLATE 拼装 / 谓词构造
          drivers.py  ODBC 驱动优选
          connstr.py  连接串构造
          models.py   数据载体
```

分层收益：`matcher / sqlbuild / connstr / drivers / models` 无任何 IO 依赖，可脱离数据库直接单测；`engine` 依赖注入连接工厂，可用假连接做行为测试。

## 4. 核心设计决策

### D1 两阶段检索的执行策略

| 阶段 | 策略 | 理由 |
| --- | --- | --- |
| A 字段定位 | 一次性拉取全库列元数据到内存，**客户端过滤** | 单个数据库的列元数据量级很小（万级行以内），一次往返即可；切换匹配模式/大小写时零成本重算，且语义完全由 Python 掌控、可单测 |
| B 内容定位 | 对每个命中列，**逐列下推 SQL** | 数据量不可预知，必须依靠数据库索引与条件下推；跨列合并到一条 SQL 会失去可中断性与进度可见性 |

阶段 A 的元数据查询：

```sql
SELECT c.TABLE_SCHEMA, c.TABLE_NAME, t.TABLE_TYPE, c.COLUMN_NAME, c.DATA_TYPE
FROM   INFORMATION_SCHEMA.COLUMNS AS c
JOIN   INFORMATION_SCHEMA.TABLES  AS t
       ON t.TABLE_SCHEMA = c.TABLE_SCHEMA AND t.TABLE_NAME = c.TABLE_NAME
WHERE  t.TABLE_TYPE IN ('BASE TABLE', 'VIEW')
ORDER  BY c.TABLE_SCHEMA, c.TABLE_NAME, c.ORDINAL_POSITION
```

### D2 匹配语义矩阵

| 阶段 | 精准 | 模糊 |
| --- | --- | --- |
| 字段名 | `column.casefold() == keyword.casefold()` | `keyword.casefold() in column.casefold()` |
| 内容 | `[col] COLLATE <X> = ?` | `[col] COLLATE <X> LIKE ? ESCAPE '\'`，参数 `%关键词%` |

大小写策略映射：

- 忽略大小写 → `<X> = Latin1_General_CI_AS`
- 区分大小写 → `<X> = Latin1_General_CS_AS`

### D3 为什么强制显式 COLLATE，而不用服务器默认排序规则

SQL Server 是否区分大小写由**列/数据库排序规则**决定，默认安装多为 `*_CI_*`（不区分），但也有大量服务器部署为 `*_CS_*`。若不做干预，界面上的「忽略大小写」勾选项在 CS 服务器上会静默失效——这是隐性行为，不可接受。

因此对内容检索一律追加显式 `COLLATE`，使行为与服务器无关。

**为何选 `Latin1_General_*` 而非 `Chinese_PRC_*`：** `Chinese_PRC_*` 属非 Unicode 排序规则，与代码页 936 绑定；将其显式应用到一个其他代码页的 `varchar` 列上会引入隐式转换与报错风险。`Latin1_General` 兼容任意代码页，对 Unicode 数据比较语义正确，且大小写折叠仅作用于拉丁字母——恰是本需求所需（中文无大小写概念，不受影响）。

### D4 并发模型

- **元数据发现**：单连接、单查询，无需并发。
- **内容检索**：`ThreadPoolExecutor(max_workers=N)`，任务粒度 = 一个 `(schema, table, column)`。
- **连接管理**：pyodbc 的连接对象**不是线程安全的**，因此每个工作线程持有各自独立连接（`threading.local`），不复用、不共享。连接数上限 = 线程数，默认 `min(8, CPU×2)`，界面可调。
- **取消机制**：`threading.Event` 置位后，工作线程在**任务边界**检查并放弃后续任务；正在执行的单条语句依靠 `query timeout` 收敛。这是可接受的取舍——绝大多数单表探测能在秒级返回，无需代价高昂的连接中断。
- **UI 线程约束**：工作线程只向 `queue.Queue` 投递事件（进度 / 命中 / 报错 / 结束），UI 用 `after(80ms)` 轮询消费。**绝不在子线程操作 Tk 控件**。

### D5 安全与资源保护

| 项 | 措施 |
| --- | --- |
| 只读保证 | 全局仅使用 `SELECT` 与 `INFORMATION_SCHEMA` 查询，代码中不存在任何 DDL/DML |
| SQL 注入 | 值一律用 `?` 参数化；标识符无法参数化，故实现 `quote_ident()` 将 `]` 双写后以 `[...]` 包裹（如 `a]b` → `[a]]b]`） |
| 生产库锁等待 | 内容探测默认启用 `WITH (NOLOCK)`，避免与业务写入争锁；代价是可能脏读，对「是否存在」这类探测可接受 |
| 长查询 | 可配置语句超时；超时按「未命中」处理并记录告警，不阻断整体流程 |
| 扫描规模 | 可配置最大检索列数上限，防止误配导致全库全列长时间扫描 |
| 命中判定 | 默认「存在性判定」（`SELECT TOP 1`），可切换为「统计行数」（`COUNT_BIG`，较慢） |

### D6 界面内输出（不落盘）

按需求方选择，结果不写文件。界面提供：

1. **结果表**：`Schema | 对象名 | 类型(表/视图) | 命中列 | 命中行数/状态 | 示例值`
2. **运行日志**：带时间戳的阶段进展、告警与错误。
3. **状态栏**：目标列数 / 已完成 / 命中数 / 耗时。
4. 结果表支持「复制选中行」「复制全部」到剪贴板，便于人工转发。

### D7 配置持久化

保存于 `%APPDATA%\MssqlFieldFinder\config.json`：服务器、端口、库名、认证方式、驱动、超时、线程数等。**密码默认不落盘**，仅当显式勾选「记住密码」时才写入。

### D8 连接方案的「多套并存」（v1.1 新增）

需求：连接设置可保存多个方案供选择。设计要点：

| 项 | 决策 | 理由 |
| --- | --- | --- |
| 存储文件 | 独立于 `config.json` 的 `connections.json` | 语义分离：`config.json` 是「上次使用值」兜底，`connections.json` 是「命名方案集合」。混在一个文件里会让「另存为」这类操作变得难以推理 |
| 方案内容 | **只含连接字段**（`CONNECTION_KEYS` 白名单） | 检索条件不是连接属性；若一并存入，切换方案会意外覆盖用户的检索条件 |
| 字段白名单维护 | 在 `profiles.py` 显式声明，并用守卫用例断言其与 `config.FIELDS` 的「连接设置」分组一致 | 两处声明必然漂移，用测试把漂移变成红灯 |
| 「记住密码」的作用域 | **存储级**（对所有方案生效），而非挂在某个方案上 | 用户心智是「本机要不要存密码」，不是「这一套方案要不要存」。开启时保存全部方案密码，关闭时全部剔除 |
| 写入方式 | 临时文件 + 原子替换 | 写入中断不会损坏既有配置，用户不会因为一次异常而丢失全部方案 |
| 升级兼容 | 首次运行若无方案文件但 `config.json` 已有服务器地址，自动生成「默认方案」 | 避免老用户升级后连接信息凭空消失 |
| 删除当前方案 | 自动切到剩余方案并**同步载入其参数** | 否则界面显示「当前方案 = A」而表单仍是 B 的参数，属静默不一致（该缺陷由界面用例捕获） |

### D9 结果逐字段复制（v1.1 新增）

需求：命中结果中每个字段都要能复制。提供三条等价入口，覆盖不同操作习惯：

| 入口 | 行为 |
| --- | --- |
| 右键菜单 | 复制单元格 / 复制整行 / 复制选中行 / 复制该列全部 / 复制全部结果 / 全选 |
| 双击单元格 | 直接复制该字段值 |
| Ctrl+C | 复制选中行（无选中时复制全部） |

实现要点：

- 单元格定位依赖 `identify_row` + `identify_column`，并把列号映射回列键，而不是依赖硬编码顺序；落在表头或空白区域时返回空值，菜单项置灰。
- 多行导出统一走 `tsv_for(items, include_header)`，表头取自 `COLUMN_TITLES`，保证任何入口产出的文本都可直接粘进 Excel。
- 反馈显示在结果表下方的一行提示中（而非状态栏），并 4 秒后自动恢复操作提示——状态栏在检索期间会被进度信息持续刷新。

### D10 网格选中模型与复制入口（v1.3 重做）

需求：默认点击只选中单元格；序号列前加一列空白列用于选整行；点击列名选整列；
三态之间切换与互斥规则要明确；复制入口收敛为四项；Ctrl+C 复制「当前选中对象」。

**三态互斥模型**：用一个 `GridSelection(kind, row, col)` 承载选中态，`kind ∈ {none, cell, row, col}`。
任一 setter 都会重置其余两者——互斥不是靠多个布尔量互相清零，而是**结构上只能表示一种状态**，
从根上避免「行和列同时被选中」这类非法组合。

| 操作 | 结果 | 视觉实现 |
| --- | --- | --- |
| 点击数据单元格 | 选中该单元格 | 该格四边蓝色边框 |
| 点击空白控制列 | 选中该行 | Treeview 原生整行高亮 |
| 点击列名 | 选中该整列 | 该列四边蓝色边框 |
| 点击表头分隔线 | 不改变选中（保留原生拖拽调列宽） | — |
| 点击表格空白区 | 清空选中 | — |
| 双击单元格 | 选中并复制该单元格 | 同上 |

**单元格高亮的实现难点**：Tk 的 Treeview 原生只支持整行选中，无法高亮单个单元格；
若用一个带底色的控件覆盖上去，又会盖住单元格文字。因此改用**四条 2px 边框**
（上/下/左/右四个 `tk.Frame` 以 `place()` 定位）围出轮廓——只画边框、不填内部，
文字完全不被遮挡。

**边框随滚动/缩放同步**：覆盖层依赖 `bbox()` 的实时坐标，故在
`<Configure>`、`<MouseWheel>`、以及被包装过的纵向/横向滚动条命令上触发
`after_idle` 合并式的重绘；目标滚出可视区时直接隐藏，避免把边框画在错误位置。

**空白控制列**：首列 `sel`，标题为空、宽 34px。它不参与单元格/整列选中，
也不出现在任何 TSV 导出里（否则粘贴进 Excel 会多出一个空列）——由
`DATA_KEYS = COLUMN_KEYS[1:]` 与 `EXPORT_KEYS` 表达。

**复制入口（收敛为四条 + 两条快捷键）**：

| 入口 | 行为 |
| --- | --- |
| 右键菜单「复制单元格」 | 复制光标所在单元格 |
| 右键菜单「复制所在行」 | 复制光标所在整行（TSV，不含空白列） |
| 右键菜单「复制所在列」 | 复制该整列（含表头） |
| 右键菜单「复制全部结果」 | 复制全部行（含表头） |
| 双击单元格 | 复制该单元格 |
| Ctrl+C | 按当前选中对象分派：格 → 单元格；行 → 整行；列 → 整列 |

目标解析的优先级统一为「显式参数 > 右键上下文 > 当前选中态」，避免菜单项因
上下文缺失而静默失败；确实无目标时给出可操作的提示文字而非静默返回。

### D11 连接设置迁入弹窗 + ODBC 驱动检测（v1.3）

需求：连接设置不直接显示在主窗口，只通过新增/编辑方案在弹窗中展示与编辑；
若无可用 ODBC 驱动，在 ODBC 配置项旁显示红色提示并提供官方下载超链接。

- **分组重排**：`FIELDS` 的 `GROUP_CONNECTION` 不再进入主窗口渲染列表 `GROUPS`；
  `remember_password` 从「连接设置」移到「配置方案」——它是存储级偏好而非连接参数，
  放在方案弹窗里会让「这个开关只影响当前方案」产生歧义。
- **主窗口只保留**：配置方案（下拉 + 新增/编辑/删除 + 记住密码 + 文件路径提示）、
  检索条件、高级设置。
- **弹窗**：`ConnectionDialog` 复用 `ScalarRow` 按 schema 渲染全部连接字段；
  方案名称在弹窗内可改，因此「重命名」不再是独立按钮。
- **校验分级**：方案名称 / 服务器 / 数据库为空属**硬错误**，直接拦截；
  凭据不完整（SQL 认证缺用户名或密码）属**软错误**，弹确认框后允许保存——
  用户可能想先存参数、稍后补密码。
- **驱动缺失不阻断保存**：否则在没有驱动的机器上连一条方案都存不下来。
- **红色提示**：`drivers.detect_sql_server_driver()` 返回空串即视为「无可用驱动」，
  在 ODBC 驱动行紧下方插入一条红色带下划线的 `tk.Label`，`cursor="hand2"`，
  点击调用 `webbrowser.open()` 打开官方下载页。用「档位优选」而非「列表非空」
  作为判定依据——机器上可能装着 Access/Excel 驱动但没有任何 SQL Server 驱动。

### D12 配置文件迁至项目路径 + 剔除默认内容（v1.3）

需求：`config.json` 与 `connections.json` 的存放路径调整到项目路径下，
并清除文件中的默认配置内容。

- **路径解析集中到 `src/paths.py`**：优先级为环境变量 `MFF_HOME` >
  打包后的可执行文件目录（`sys.frozen`）> 源码所在项目根。集中一处便于测试与部署。
- **只读回退**：新路径不存在而旧 `%APPDATA%\MssqlFieldFinder` 下的文件存在时，
  读取旧文件；**不删除、不修改**旧文件。避免升级后已配置的连接方案凭空消失。
  若旧 `config.json` 里带有服务器地址，还会据此播种一个「默认方案」。
- **剔除默认内容**：落盘前把取值与字段默认值逐项比较，只保留**有差异**的项。
  于是：
  - 用户什么都没改时**根本不生成文件**（`save()` 返回 `None`）；
  - 已经存在的文件在取值回归默认后会被写成 `{}`，而不是留下陈旧的默认值。
  目的很直接——打开文件一眼就能看出「我改过什么」，而不是在几十行默认值里找差别。

### D13 双击单元格 → 打开「命中数据」窗口（v1.4）

需求：双击单元格时，若已启用内容检索则打开新窗口展示该表中查到的数据；未启用则不做任何动作。

| 项 | 决策 |
| --- | --- |
| 触发条件 | 以**当前**「启用内容检索」勾选状态为准；未勾选则回调直接返回，界面无任何反馈 |
| 查询参数 | 使用**上一次实际执行**的请求（`_last_request`），而非当前界面取值。否则用户改了关键词再双击，明细与已列出的结果会对不上 |
| 语句构造 | 新增 `sqlbuild.build_detail_sql`：`SELECT TOP (n) * FROM 表 WITH (NOLOCK) WHERE <与探测阶段完全相同的谓词>`。复用同一套 `build_content_predicate`，**杜绝「列表说命中、明细却查不到」** |
| 行数上限 | 默认 200、硬上限 5000。双击是即兴操作，必须防止误点大表把内存打满 |
| 取数方式 | 后台线程 + `after` 轮询；明细是低频操作，自建连接用完即关，不复用扫描期连接池 |
| 双击不再是「复制」 | 复制已由右键四项与 Ctrl+C 完整覆盖，双击腾给更高价值的「看数据」 |

窗口内容：表/字段/条件摘要（含匹配模式、大小写与行数上限）、动态列的 Treeview、
状态行（`共 N 行` / `已达上限` / 查询失败原因）、以及「复制全部数据」。行内数据全部转为文本展示，
空值显示为空串，便于直接粘进 Excel。

### D14 记住密码与测试连接并入弹窗（v1.4）

- **归属**：`remember_password` 从主窗口移入弹窗，仍是**存储级**偏好（对所有方案生效），
  默认**勾选**。它被刻意排除在 `CONNECTION_KEYS` 之外，因此不会随方案切换而改变。
- **测试连接**：从工具栏移入弹窗，因为在填写参数的地方测试最顺手。
- **结果反馈**：窗口底部一行「指示灯 + 文案」——灰=未测试、黄=测试中、绿=测试成功、红=连接失败。
  指示灯是一个 16px 的 `Canvas` 圆点，颜色随状态切换；文案颜色与圆点保持一致，
  这样色觉不敏感的用户也能靠文字判断结果。
- **不阻塞界面**：连接测试在后台线程执行（登录超时可达 10s），界面经 `after` 轮询取结果；
  测试期间按钮置灰，重复点击被忽略。
- **失败也分级**：参数不完整（如缺服务器）时直接亮红灯并给出具体项，不发起网络连接。

### D15 主窗口进一步减负（v1.4）

1. **移除「保存设置」按钮**：改为主窗口关闭时静默落盘（`_save_settings_quietly`）。
   方案的新增/编辑本身就是显式保存动作，再留一个全局保存按钮只会让人犹豫「我到底存了没」。
2. **关键词不再持久化**：`field_keyword` 与 `content_keyword` 标记 `persist=False`——
   既不写入配置，读取时也忽略。理由：检索词是一次性输入，若下次启动还在，
   用户会误以为已经清空而过早点击检索。为此在 `Field` 上引入 `persist` 标志，
   而不是在保存逻辑里硬编码字段名，便于以后按同一规则扩展。
3. **路径文字改为按钮**：配置方案框里不再显示两行完整路径（在窄面板里必然换行折断、很难读），
   改为「打开设置文件」「打开方案文件」两个按钮，用系统默认程序打开；
   文件尚未生成时（各项均为默认值时不会落盘）改为打开所在目录并给出说明。

### D16 测试结果文案：精简 + 自动换行（v1.5）

需求：成功文案只显示「结果 / 当前库 / 登录身份」；内容超出窗口宽度时自动换行。

- **结构化探测结果**：把 `engine.probe_server()` 拆成
  `probe_server_info() -> ServerInfo(database, login, version)` 与两个呈现方法：
  `summary()` 供弹窗（结果/当前库/登录身份），`full_text()` 供日志（追加版本号）。
  这样「界面要短、日志要全」的差异由数据层提供两种视图，而不是在界面里做字符串裁剪——
  裁剪会带来「版本号被截一半」这种难看的输出。
- **换行宽度在布局完成后确定**：`_Lamp` 新增 `set_wrap(pixels)`，在
  `ConnectionDialog._center_on()` 里用 `form.winfo_reqwidth() - 40` 计算。
  注意用 `winfo_reqwidth()` 而非 `winfo_width()`——窗口尚未映射时后者返回 1，
  会让 wrap 退化成最小值。这保证了长文案在窗口内折行，而不会把弹窗撑宽。

### D17 检索参数落盘时机与关键词「写入不读回」（v1.5）

需求：每次点击「开始检索」后自动把检索条件写入设置文件；同时（上一轮的要求）
两个关键词每次启动仍应为空。

两者看似冲突，实际可以用**写入与读回分离**同时满足：

| 字段 | 写入 | 读回 | 效果 |
| --- | --- | --- | --- |
| 字段名关键词 / 内容关键词 | 是 | **否** | 设置文件里能看到搜过什么，界面每次启动仍是空的 |
| 匹配模式 / 忽略大小写 / 启用内容检索 / 高级设置 | 是 | 是 | 常规持久化 |

实现上把 `Field.persist` 拆成 `persist`（是否写入）与 `restore`（是否读回）两个标志，
而不是在保存/读取逻辑里硬编码字段名。

落盘时机放在**校验通过之后、真正发起扫描之前**——校验失败时不写，
因为此时用户填的多半是半成品，写进去只会污染文件。

### D18 记住密码按方案独立（v1.5）

需求：记住密码只影响当前方案。

原先它是 `connections.json` 里的一个顶层布尔，关闭时会剔除**所有**方案的密码。
现改为顶层 `remember` 映射（方案名 -> 布尔），缺省视为「记住」：

- `remember_for(name)` 查询，`upsert(name, values, remember=…)` 写入；
- `blank_passwords()` 只清空开关为关闭的那些方案；
- 落盘时只写**关闭**的那些（默认的「记住」不写），保持文件精简；
- 旧版的顶层 `remember_password` 在读取时迁移为「当时已存在的方案都不记住」，
  保证升级后既有行为不变。

弹窗里的复选框改为按当前方案预填，提示也改成「各方案独立设置」。

### D19 并发默认值与提示文字布局（v1.5）

**并发线程数**默认值改为按本机核数推导：`钳制(CPU 核数, 4, 12)`。

- 下限 4：检索是网络 I/O 密集型，线程数低于核数没有意义；
- 上限 12：目标是一台共享的生产库，线程过多会加剧锁竞争与服务器负载。

配套改动：`defaults()` / `effective_default()` 支持动态默认值，
这样「按核数算出的值」不会被 `build_payload` 误判成「用户改过」而写进配置文件。
字段提示直接显示推导依据（如「本机 12 核 · 建议 4~12」），启动日志也记一行。

**提示文字布局**的几处调整：

| 问题 | 处理 |
| --- | --- |
| 左侧表单是「标签 + 控件 + 提示」三列，原先面板太窄，提示被挤掉或折断 | 分隔条从 34% 放宽到 38%（下限 440、上限 580）；提示换行列宽 132 → 150 |
| 输入框偏宽（22 字符）挤占提示列 | 默认宽度收到 18 字符（驱动下拉 26 保留） |
| 部分提示偏长，在窄列里仍会折行 | 逐条改写为 ≤ 10 字的短句（如「关闭时仅判定存在，更快」→「关闭则只判定存在」） |
| 结果表下方提示可能被截断 | 绑定 `<Configure>` 按可用宽度动态设置 `wraplength` |
| 弹窗中「连接设置 / 测试结果 / 按钮」三区黏连 | 各区块之间加 `ttk.Separator` 分隔 |
| 提示与控件顶部对齐不整齐 | 提示标签改为 `sticky="nw"` 并与控件行留出统一内边距 |

### D20 打包为可独立运行的可执行程序（v1.6）

需求：产出可直接运行的可执行程序，并提供可复用的一键打包脚本与环境说明。

**工具与形态**：PyInstaller 6.22.3 + 单文件（onefile）模式，产物
`MssqlFieldFinder\MssqlFieldFinder-v<版本>.exe`（约 10.2 MB，自包含 Python 运行时与 Tcl/Tk）。

**产物命名规则**：**目录名 = 程序名（不带版本号与扩展名），文件名在其后追加版本号**。

| 位置 | 取值 | 来源 |
| --- | --- | --- |
| 产物目录 | `MssqlFieldFinder\` | `src\__init__.py` 的 `__app_name__`，由 `bat\build.bat` 拼进 `--distpath` |
| 产物文件名 | `MssqlFieldFinder-v1.6.0.exe` | `__app_name__` + `-v` + `__version__`，由 spec 的 `EXE_NAME` 拼接 |

这样安排的好处：同一目录可累积多个版本的 exe（便于回退比对），
而目录名固定不变，脚本、快捷方式与文档里的路径不必随版本一起改。

有一点需要注意：**产物目录由 `--distpath` 决定，spec 里管不到它**。为了让目录名与
spec 里的 `BASENAME` 不出现两份定义，`bat\build.bat` 先从 `src\__init__.py` 读出程序名，
再同时用于「拼 `--distpath`」与「通过 `MFF_NAME` 环境变量注入 spec」，
保证目录名与产物名前缀天然一致。

| 决策 | 取值 | 理由 |
| --- | --- | --- |
| 单文件 vs 目录版 | **单文件** | 分发只需拷一个文件；代价是启动需解包到临时目录（1~3 秒）。spec 末尾附了切目录版的写法 |
| 控制台 | **无控制台** | GUI 程序不需要黑框；但保留 `disable_windowed_traceback=False`，启动即崩时会弹窗而不是静默退出 |
| 配置目录 | `sys.executable` 的父目录 | exe 放哪、配置就生成在哪（即产物目录内），符合「绿色软件」的直觉 |
| 构建参数位置 | **只在 `MssqlFieldFinder.spec`** | 脚本与 spec 各写一份必然漂移；脚本只负责找环境、读名称与版本、拼 `--distpath`、报结果 |
| 名称/版本来源 | `src/__init__.py` 的 `__app_name__` / `__version__` | 单一来源，脚本调 `main.py --app-name / --version` 读取，窗口标题用版本号 |
| 排除项 | numpy / pandas / matplotlib / PIL / PyQt / pytest 等 | 本工具一个都不用，排除后体积明显下降 |
| 显式 hiddenimports | `pyodbc` | 它在 `drivers.py` 里是惰性导入（为了让纯逻辑测试不必装 pyodbc），显式声明更稳妥 |

**部署自检**：`main.py` 增加 `--version` 与 `--check`。窗口程序默认没有控制台，
因此 `attach_console()` 会尝试附着到调用方的 cmd（`AttachConsole(-1)` + 打开 `CONOUT$`），
附着失败则把结果写到 exe 同级的 `selfcheck.log`。
`_check` 本身要「打不还手」——环境探测异常时打印原因并返回 0，而不是抛栈把最有用的信息丢掉。

**踩坑记录（供后续维护参考）**：

1. `SPECPATH` 在 PyInstaller 中指向 spec 所在**目录**而非文件；写成 `.parent` 会多上跳一层。
   现用 `is_file()` 判断，两种语义都兼容。
2. cmd 的 `for /f ('命令')` 在命令行以引号开头且含两段带引号的绝对路径时会截断命令、
   取不到输出。故先 `pushd` 到项目目录再用相对路径调用。
   这类失败是**静默的**（版本号退化成默认值），所以脚本对关键取值都要有兜底并显式打印。

## 5. 关键取舍与已知约束

1. **依赖 ODBC 驱动**：目标机需安装 Microsoft ODBC Driver for SQL Server（本机已有 17 / Native Client 11）。工具启动时会自动探测并优选。
2. **需要列级 SELECT 权限**：无权限的列会在内容检索阶段返回错误，工具记录为「跳过（无权限）」而非中断。
3. **结果表 Treeview 在极端命中量下的性能**：界面最多渲染前 N 条（默认 2000），超出部分仅在日志中给出计数，避免 UI 卡死。
4. **视图的内容检索**：视图可查询，但 `NOLOCK` 提示在视图上会作用于其展开层，属预期行为。
5. **大小写折叠的语言学边界**：字段名过滤使用 Python `casefold()`（对 Unicode 更强），内容检索使用 SQL 排序规则折叠（对拉丁字母）。两者对中文均无影响，但因实现路径不同而存在理论差异，已在文档中显式说明。
